## Design Context

### Users

Developers evaluating Matchbox and checking its browser integration use this example. The example now demonstrates examples-to-browser training and local customer filtering.

### Brand Personality

The supplied brief calls for ordinary software primitives, strict outputs, and no AI theater. Keep the presentation direct, restrained, and functional.

### Aesthetic Direction

The website follows the rendered Eve and vGPU sites as design references: a dark graphite surface, precise Geist typography, a distinctive sculptural Matchbox hero, and interactive code that demonstrates the product. Keep Fluid Functionalism controls, adapted to this visual system. Avoid beige SaaS layouts, repeated marketing sections, and internal release-status commentary in the product story. Documentation navigation should preserve the application shell without full-page loading flashes.

### Design Principles

1. Show only working capabilities.
2. Keep package verification understandable at a glance.
3. Use Fluid's component behavior with explicit keyboard focus and reduced-motion handling.
4. Keep the layout usable on narrow screens.
