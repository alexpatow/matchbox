## Design Context

### Users

Developers evaluating Matchbox and checking its browser integration use this example. The first ticket only proves that the React app can consume the local library.

### Brand Personality

The supplied brief calls for ordinary software primitives, strict outputs, and no AI theater. Keep the presentation direct, restrained, and functional.

### Aesthetic Direction

The user requested a very minimal example using [Fluid Functionalism](https://www.fluidfunctionalism.com/) components. Use a quiet light surface and the component system's variable font. Do not build the customer-filter demo until its ticket.

### Design Principles

1. Show only working capabilities.
2. Keep package verification understandable at a glance.
3. Use Fluid's component behavior with explicit keyboard focus and reduced-motion handling.
4. Keep the layout usable on narrow screens.
