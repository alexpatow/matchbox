## Design Context

### Users

Developers evaluating Matchbox and checking its browser integration use this example. The example now demonstrates examples-to-browser training and local customer filtering.

### Brand Personality

The supplied brief calls for ordinary software primitives, strict outputs, and no AI theater. Keep the presentation direct, restrained, and functional.

### Aesthetic Direction

The user requested a very minimal example using [Fluid Functionalism](https://www.fluidfunctionalism.com/) components. Use a quiet light surface and the component system's variable font. BOO-46 authorizes the minimal customer-filter demo using the existing design direction.

### Design Principles

1. Show only working capabilities.
2. Keep package verification understandable at a glance.
3. Use Fluid's component behavior with explicit keyboard focus and reduced-motion handling.
4. Keep the layout usable on narrow screens.
